디지털 포렌식은 컴퓨터, 스마트폰, 네트워크 등에 남은 데이터를 조사해 사건의 흐름을 재구성하는 과정이다.

파일을 복구하는 것만으로 끝나지 않는다.

어떤 데이터를 어떻게 확보했고, 그 데이터로 무엇을 확인할 수 있는지 설명해야 한다.

```text
증거 확보
-> 원본 보존
-> 흔적 추출
-> 사건 흐름 분석
-> 결과와 한계 기록
```

핵심은 증거의 무결성과 분석 과정의 재현성이다. [NIST의 디지털 포렌식 정의](https://csrc.nist.gov/glossary/term/digital_forensics)도 정보의 무결성을 보존하면서 데이터를 수집하고 분석하는 과정을 강조한다.

---

## 디지털 포렌식의 목적

포렌식은 흔적을 근거로 사건에 관한 질문에 답한다.

| 질문 | 확인할 수 있는 자료 |
| --- | --- |
| 언제 접근했는가? | 인증 로그, 접속 기록 |
| 어떤 파일을 사용했는가? | 파일 시스템 메타데이터, 최근 사용 기록 |
| 어떤 프로그램이 실행되었는가? | 실행 관련 흔적, 프로세스 정보 |
| 어디로 통신했는가? | 네트워크 로그, 패킷, DNS 기록 |
| 어떤 데이터가 이동했는가? | 전송 기록, 외부 저장장치 흔적, 파일 내용 |

다만 기록이 있다는 사실과 실제 행위자를 특정하는 것은 별개의 문제다.

계정 사용 기록만으로 해당 계정의 소유자가 직접 행동했다고 단정할 수 없다.

---

## 디지털 포렌식의 종류

디지털 포렌식은 분석 대상에 따라 디스크 포렌식, 메모리 포렌식, 모바일 포렌식 등으로 나뉜다.

실무에서 사용하는 분야 명칭이며, 서로 완전히 분리된 영역은 아니다. 한 사건에서 여러 분야의 분석을 함께 수행할 수 있다.

| 분야 | 주요 대상 | 분석 예시 |
| --- | --- | --- |
| 디스크 포렌식 | HDD, SSD, 디스크 이미지 | 파일, 삭제 흔적, 파티션 분석 |
| 메모리 포렌식 | RAM 덤프 | 프로세스, 메모리 내 코드, 연결 정보 분석 |
| 네트워크 포렌식 | 패킷, 방화벽·DNS 로그 | 통신 흐름과 의심 연결 분석 |
| 모바일 포렌식 | 스마트폰 데이터, 백업 | 앱 데이터와 사용 기록 분석 |
| 클라우드 포렌식 | 감사 로그, 객체, 스냅샷 | 계정 활동과 리소스 변경 분석 |

한 가지 자료로 전체 사건이 설명되는 경우는 드물다.

디스크에서 찾은 실행 흔적을 인증 로그와 네트워크 기록으로 교차 확인하면 해석의 근거가 더 명확해진다.

---

### 디스크 포렌식 (Disk Forensics)

HDD, SSD, USB 저장장치 등에 저장된 데이터를 분석하는 분야다.

파티션과 파일 시스템 구조부터 파일 내용, 메타데이터, 삭제된 데이터까지 조사한다.

```text
분석 대상: 저장장치 또는 디스크 이미지
주요 흔적: 파일, 디렉터리, 파일 시스템 메타데이터, 비할당 영역
활용 예시: 삭제 파일 복구, 파일 이동 흔적과 프로그램 실행 흔적 조사
```

삭제된 데이터가 남아 있어야 복구할 수 있다. 덮어쓰기나 SSD의 TRIM, 암호화 상태 등에 따라 확보 가능한 내용이 달라진다.

---

### 메모리 포렌식 (Memory Forensics)

컴퓨터의 휘발성 메모리인 `RAM`에 남아 있는 데이터를 분석하는 분야다.

수집 시점의 프로세스, 로드된 모듈, 네트워크 연결 정보, 메모리 내 악성 코드를 조사할 수 있다.

상황에 따라 복호화에 사용되는 키나 사용자 데이터가 메모리에 남아 있을 수도 있다. 모든 키와 정보를 확보할 수 있는 것은 아니다.

```text
분석 대상: 메모리 덤프
주요 흔적: 프로세스, 모듈, 연결 정보, 메모리 내 데이터
활용 예시: 의심 프로세스 조사, 메모리에만 존재하는 악성 코드 분석
```

RAM은 전원이 꺼지면 내용이 사라질 수 있다. 수집 도구 자체도 메모리를 사용하므로 수집 과정에서 발생한 변경을 기록해야 한다.

---

### 모바일 포렌식 (Mobile Forensics)

스마트폰과 태블릿 같은 모바일 기기의 데이터를 분석하는 분야다.

통화 기록, 메시지, 사진, 앱 데이터, 위치 관련 기록과 백업 등을 조사한다.

```text
분석 대상: 모바일 기기, 추출 데이터, 기기 백업
주요 흔적: 통화·메시지 기록, 앱 데이터베이스, 사진 메타데이터
활용 예시: 사용자 활동 재구성, 앱 사용 기록과 파일 전송 흔적 조사
```

기기 모델, 운영체제 버전, 잠금과 암호화 상태에 따라 수집 범위가 달라진다. 백업에 포함된 데이터와 실제 기기 전체의 데이터도 구분해야 한다.

---

### 네트워크 포렌식 (Network Forensics)

네트워크에서 발생한 통신을 분석해 접근 경로와 공격 흐름을 조사하는 분야다.

패킷뿐 아니라 방화벽, 프록시, DNS, VPN 등에서 생성한 로그도 활용한다.

```text
분석 대상: 패킷 캡처와 네트워크 장비·서비스 로그
주요 흔적: 출발지·목적지 주소, 포트, 요청, 연결 시각, 전송량
활용 예시: 침입 경로 조사, 외부 서버와의 통신 및 정보 유출 정황 분석
```

암호화된 통신은 패킷만으로 내용을 확인하기 어렵다. 수집 위치와 기간에 따라 관찰 범위가 달라지고, IP 주소만으로 실제 행위자를 특정할 수는 없다.

---

### 클라우드 포렌식 (Cloud Forensics)

클라우드 서비스에서 발생한 계정 활동과 데이터·리소스 변경을 분석하는 분야다.

감사 로그, 가상 머신의 디스크 스냅샷, 객체 저장소 기록 등을 조사할 수 있다.

```text
분석 대상: 클라우드 감사 로그, 스냅샷, 저장된 객체
주요 흔적: API 호출, 인증, 권한 변경, 리소스 생성·삭제 기록
활용 예시: 계정 탈취 조사, 비정상 리소스 생성과 데이터 접근 분석
```

서비스별 로그 설정, 보존 기간, 접근 권한에 따라 확보할 수 있는 증거가 달라진다. 스냅샷도 생성 시점과 포함 범위를 확인해야 한다.

---

### 침해사고 대응 (Incident Response)

침해사고 대응은 해킹이나 랜섬웨어 등 보안 사고를 조사하고, 피해 확산을 억제하며, 서비스를 복구하는 활동이다.

디스크나 메모리처럼 분석 대상에 따른 포렌식 종류라기보다, 여러 포렌식 기법을 활용하는 대응 업무에 해당한다.

```text
사고 탐지와 범위 확인
-> 증거 수집 및 침입 경로 조사
-> 피해 확산 억제
-> 악성 요소 제거와 복구
-> 원인 분석 및 재발 방지
```

실제 대응에서는 조사와 확산 억제가 병행될 수 있다. 예를 들어 감염 장비를 네트워크에서 격리하면서 메모리, 디스크, 인증 로그를 확보한다.

초기 침입 경로, 공격자의 활동, 유출 가능성, 남아 있는 접근 수단을 조사할 때 디지털 포렌식을 활용한다.

`DFIR`은 `Digital Forensics and Incident Response`의 약자로, 디지털 포렌식과 침해사고 대응을 함께 다루는 표현이다.

## 증거 보존의 기본 원칙

### 원본과 분석본 분리

확보한 원본은 보존하고, 분석은 별도의 작업 복사본에서 수행한다.

저장장치 전체를 조사할 때는 포렌식 이미지를 확보할 수 있다.

일반적인 파일 복사는 선택한 파일을 복사하지만, 비트 단위 디스크 이미징은 수집 범위에 따라 파일 시스템 구조와 비할당 영역까지 포함한다.

```text
원본 저장장치
-> 포렌식 이미지 확보
-> 이미지 검증 및 보존
-> 작업 복사본 생성
-> 작업 복사본 분석
```

저장장치 수집에는 쓰기 방지 장치를 사용할 수 있다.

다만 실행 중인 시스템의 메모리를 확보하는 라이브 수집은 시스템 상태에 영향을 준다. 사용한 도구, 실행 시각, 예상되는 변경을 함께 기록해야 한다.

---

### 해시로 무결성 확인

해시는 데이터에서 계산하는 고정 길이 값이다.

예를 들어 이미지 파일을 확보한 직후와 분석용으로 복사한 뒤 `SHA-256` 값을 비교할 수 있다.

```text
확보한 이미지의 SHA-256
== 작업 복사본의 SHA-256
-> 같은 바이트 내용인지 확인하는 근거
```

해시가 같다는 것은 비교 대상의 내용이 같다는 근거다.

수집이 적절했는지, 이미지에 필요한 자료가 모두 포함됐는지, 그 자료가 사건과 관련 있는지까지 증명하지는 않는다.

또한 E01 같은 컨테이너 이미지 파일의 해시와 원본 디스크 데이터의 해시는 비교 범위가 다르다. 압축이나 메타데이터가 포함된 컨테이너 자체의 해시를 원본 디스크의 해시와 직접 비교하면 안 된다.

---

### 증거 관리 이력

`Chain of Custody`는 증거의 확보, 보관, 전달 이력을 뜻한다.

누가 언제 증거를 다뤘는지 기록해 추적할 수 있어야 한다.

| 기록 항목 | 예시 |
| --- | --- |
| 증거 식별자 | CASE-001-DISK-01 |
| 수집 대상 | 장치 모델, 일련번호, 수집 범위 |
| 수집 담당자 | 담당자 이름 또는 식별자 |
| 수집 시각 | 시간대가 포함된 시작·종료 시각 |
| 수집 방법 | 도구와 버전, 설정, 오류 |
| 무결성 정보 | 해시 알고리즘, 값, 계산 대상 |
| 전달 이력 | 전달자, 수령자, 시각, 목적 |

분석 결과뿐 아니라 그 결과를 만든 과정도 남겨야 한다.

## 디지털 포렌식 절차

[NIST SP 800-86](https://csrc.nist.gov/pubs/sp/800/86/final)은 포렌식 과정을 수집, 조사, 분석, 보고의 네 단계로 설명한다.

### 수집

조사 질문과 대상 범위를 정하고 필요한 데이터를 확보한다.

실행 중인 시스템에서는 전원이 꺼지면 사라질 수 있는 메모리와 연결 정보 등을 고려한다.

무조건 전원을 끄거나 무조건 켜 두는 방식으로 결정하지 않는다. 증거의 휘발성, 암호화 상태, 서비스 영향, 공격 지속 여부를 함께 판단한다.

### 조사

확보한 데이터에서 필요한 정보를 추출하고 정리한다.

```text
파일 시스템 구조 확인
-> 파일 및 메타데이터 추출
-> 로그와 앱 데이터 파싱
-> 검색과 필터링
-> 관련 흔적 선별
```

이 단계에서는 도구의 결과와 원본 데이터의 위치를 연결해 기록한다.

### 분석

추출한 흔적을 비교해 사건의 순서와 가능한 원인을 해석한다.

시간대, 시스템 시계 오차, 로그 누락을 고려하고 서로 다른 자료가 같은 해석을 뒷받침하는지 확인한다.

### 보고

확인한 사실, 해석, 확인하지 못한 내용을 구분해 작성한다.

수집 범위, 도구와 버전, 주요 증거 위치, 분석 한계도 포함한다.

## 아티팩트란?

`Artifact`는 시스템이나 사용자의 활동으로 남는 분석 가능한 흔적이다.

Windows 환경에서는 다음과 같은 자료를 조사할 수 있다.

| 아티팩트 | 확인에 도움이 되는 내용 | 해석 시 주의점 |
| --- | --- | --- |
| 이벤트 로그 | 인증, 서비스, 시스템 이벤트 | 감사 설정과 로그 보존 상태에 따라 내용이 달라진다 |
| Prefetch | 프로그램 실행 관련 정보 | 환경에 따라 생성되지 않을 수 있다 |
| LNK 파일 | 바로가기 대상과 경로 정보 | 현재 파일 존재 여부나 열람 행위를 단독으로 증명하지 않는다 |
| Jump List | 앱과 관련된 최근 항목 | 앱의 동작과 기록 방식을 함께 확인한다 |
| 레지스트리 | 설정, 장치, 사용자 환경 관련 정보 | 키마다 의미와 갱신 조건이 다르다 |
| 브라우저 데이터 | 방문 기록, 다운로드 기록 | 동기화, 삭제, 사생활 보호 모드 등의 영향을 받는다 |
| NTFS 메타데이터 | 파일 정보와 변경 관련 흔적 | 타임스탬프의 의미와 조작 가능성을 고려한다 |

특정 아티팩트가 없다고 해서 해당 행위가 없었다고 결론 내릴 수는 없다.

---

## 타임라인 분석

타임라인 분석은 서로 다른 자료를 시간 순서로 연결하는 방법이다.

다음은 설명을 위한 가상 사례다. 모든 시각은 `Asia/Seoul` 기준으로 정규화했다고 가정한다.

| 시각 | 관찰된 기록 | 해석 |
| --- | --- | --- |
| 10:02 | 계정 A의 원격 로그인 성공 | 해당 계정으로 접근한 세션이 존재한다 |
| 10:05 | 실행 파일 다운로드 기록 | 파일 확보 경위를 조사할 수 있다 |
| 10:07 | 해당 파일의 실행 관련 흔적 | 실행 가능성을 다른 자료와 확인한다 |
| 10:08 | 외부 주소와 통신 기록 | 프로세스와 연결의 관련성을 조사한다 |

이 기록만으로 다운로드한 파일이 악성코드라고 단정할 수는 없다.

파일 내용, 프로세스 정보, 통신 대상 등을 추가로 확인해야 한다.

원래 기록된 시각과 시간대도 보존한다. 시각을 변환할 때는 변환 기준을 기록하고, 파일 생성·수정·접근 시각을 같은 의미로 취급하지 않는다.

---

## 삭제 파일 복구와 한계

파일 삭제가 항상 데이터의 즉시 소멸을 의미하는 것은 아니다.

파일 시스템에서 참조가 제거된 뒤 데이터 일부가 남아 있다면 복구할 수 있다.

하지만 덮어쓰기, SSD의 TRIM과 내부 정리, 암호화, 파일 단편화 등으로 복구가 어려워질 수 있다.

`파일 카빙`은 파일 시스템 메타데이터 대신 데이터의 시그니처와 구조를 이용해 파일을 찾아내는 방식이다.

원래 파일명이나 경로를 되찾지 못할 수 있고, 단편화된 파일은 불완전하게 복구될 수 있다.

복구된 파일의 존재와 원래 위치, 생성 시점은 구분해서 설명해야 한다.

## 도구와 결과 검증

[Autopsy](https://sleuthkit.org/autopsy/index.php)는 The Sleuth Kit 등을 활용하는 디지털 포렌식 플랫폼이다. 파일 조사, 키워드 검색, 웹 아티팩트와 타임라인 분석 기능을 제공한다.

도구가 표시한 결과를 그대로 결론으로 옮기기 전에 다음을 확인한다.

```text
어떤 원본 데이터에서 나온 결과인가?
파서가 해석한 필드의 의미는 무엇인가?
시간대와 도구 설정은 무엇인가?
다른 흔적도 같은 해석을 뒷받침하는가?
오류나 누락이 있었는가?
```

도구는 흔적을 찾고 정리하는 데 도움을 준다.

흔적의 의미와 결론의 범위를 판단하는 것은 분석자의 역할이다.

## 보고서에 포함할 내용

| 항목 | 내용 |
| --- | --- |
| 조사 목적 | 답하려는 질문과 조사 범위 |
| 증거 목록 | 식별자, 출처, 수집 방법, 해시 |
| 분석 환경 | 운영체제, 도구 버전, 주요 설정 |
| 분석 결과 | 확인한 사실과 근거 데이터 위치 |
| 타임라인 | 시각, 시간대, 관련 사건 |

예를 들어 "공격자가 파일을 실행했다"보다 "해당 계정의 세션과 파일 실행 관련 흔적을 확인했으나 실제 사용자는 확인하지 못했다"가 증거의 범위를 더 정확하게 드러낸다.

## 정리

디지털 포렌식은 남아 있는 흔적을 수집하고 연결해 사건을 설명하는 작업이다.

원본 보존, 해시 검증, 증거 관리 이력, 교차 분석이 기본이 된다.

파일 하나나 로그 한 줄로 결론을 내리기보다, 여러 자료를 연결하고 확인 가능한 범위를 명확하게 기록해야 한다.
